1.0 Introduction  
 
The ANALYZERTM Recalculation Process Best Practice deals with MARC Management. 
 
Current users of Analyzer have communicated confusion regarding the Analyzer recalculation 
process and how it differs based on the respective dealer’s Financial Year-End. Failure to use the 
proper recalculation process will have a detrimental impact to Analyzer’s ability to accurately 
forecast the financial/performance health of contracts as well as provide accurate reporting of 
historical activity.  
 
By following the recommendations detailed in the Analyzer Recalculation Process Best Practice, 
users can be confident that all current work order and billing information is accounted for in the 
projection calculations as well as historical functionality in Analyzer. The overall benefit is 
increased accuracy of Analyzer projections.  
 
2.0 Best Practice Description 
 
The recommended process for recalculating Analyzer is communicated and put into practice 
during Analyzer training classes. However, not all training participants will immediately begin using 
Analyzer or will be regular users of the tool, resulting in confusion as to what recalculation date to 
use during the recalculation process.  
 
The Analyzer Recalculation Process Best Practice, provides the user with a recommended 
process for selecting the appropriate recalculation date as well as actually recalculating Analyzer. 
 
1) Determine the suggested Recalculation Date 
 
a) Determining the Latest Invoice Period 
 
⇒ Navigate to the View Data Tables screen and double-click Contract Cost under the 
Transaction Data heading. 
 
⇒ Use the scroll bar at the bottom of the screen until the Invoice Period column is visible. 
Select (highlight) the Invoice Period column and select 
 (Sort Descending). 
 
⇒ The first date (yyyymm) in the Invoice Period column represents the latest period work 
orders were invoiced to the customer and corresponds to the dealer’s accounting 
system. This period does not represent the date when the work order was opened. 
 
NOTE: Any work order in Analyzer without an Invoice Period value in the Contract Cost 
Table is considered Work In Process (WIP) and is included in the Analyzer projection 
regardless of the recalculation date used. 
 
b)   Determining Analyzer’s Financial Year-End  
 
⇒ In order to determine the required recalculation date, first confirm the Dealer Data File’s 
financial year-end. This is accomplished by navigating to the Administration switchboard

(1) Financial Year-End is December (If Financial Year-End is not December, please skip

(a) If the Dealer Data File’s financial year-end is December, the Recalculation Date

- Dealer Data File Year-End = December 
- ContractCost Table Invoice Period column latest period = 200605

(b) Based on the information provided above, the suggested recalculation date is 
June 1, 2005 (First of the month following the Invoice Period Month). Using this 
date will ensure Analyzer includes all work orders and customer billings through 
June 1, 2005 in the recalculation process. 
 
(2) Financial Year-End other than December 
 
(a) If the Dealer Data File is based on a financial year-end other than December, the 
latest Invoice Period must be converted back to the equivalent calendar date 
using the methodology illustrated below. 
 
- Dealer Data File Year-End = June

field value is 200610.

following the Invoice Period Month converted to the corresponding Calendar 
Date). Using this date will ensure Analyzer includes all work orders and customer 
billings through November 1, 2006 in the recalculation process.

3.0 Implementation Steps 
 
1. In order to successfully implement this Best Practice, the critical assumption is that all users 
have received basic Analyzer user training either internally or from Caterpillar.  
 
2. In addition, it is recommended that users have, at a minimum, Level 1 Microsoft Access 
training and are comfortable navigating within an Access database/tables. 
 
4.0 Benefits 
 
• Reduce user confusion when the need to recalculate Analyzer presents itself  
• Provide a globally consistent Analyzer recalculation process. (Dealers that have a Financial 
Year-End other than December will find this Best Practice especially useful). 
 
5.0 Resources Required 
 
1. Full implementation of Analyzer 1.6W is required. 
2. MS Access 2000 (full version) 
3. Having trained Analyzer users is critical to the success of this process. Users should have 
received some form of basic Analyzer training either internally or through Caterpillar. 
4. In addition, users should have a basic understanding of Microsoft Access (MS Access 2000 
Level 1).
